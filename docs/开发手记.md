## 1. 项目速览

### 1.1 数据流

```
data/flowlog.db  (SQLite)
      │  store.Days()              启动时读一次，全量进内存
      ▼
 []model.Day ──────────────┐
      │                    │  App.days（按日期倒序）
      │ store.SaveDay()    ▼
      │（一个事务）    View(c) 每帧把状态翻成元素树
      │                    │
      │                    ▼
      │           ui.List / ui.Text / ui.Checkbox …
      │                    │
```

## 2. 先理解 MyGo 原生模式的三个概念

1. `View` 是 `f(state)`，一帧可能被调用多次，里面不要有副作用。
2. `ui.Element` 只在当帧有效，**不能存**；要持久化的是 `ui.Handle`、`ui.ListState` 与业务数据。
3. 输入先写值、通知后到达；改动集合的动作交给 `OnClick` / `OnChange` 延迟执行。

### 2.1 视图是状态的函数

```go
func (app *App) View(c *ui.Context) {
    app.rollOver()      // 跨零点：把「今天」推到新的一天
    app.applyTheme(c)   // 每帧重设主题
    app.flushToasts(c)  // 把攒下的提示交给窗口

    root := ui.Row(c).Fill().AlignItems(ui.Stretch)
    root.Children(func() {
        app.sidebar(c)
        app.router.View(c, func(r *ui.Route) { /* 四个页面 */ })
    })
    app.diaryEditor(c)    // 弹层写在路由外面
    app.confirmDialog(c)
    app.onboardingDialog(c)
}
```

由此推出两条纪律：**构建过程要便宜**（别在 view 里遍历上万条数据）、
**构建过程要幂等**（同一份状态构建两次，界面应当一样）。

> 反例：在 `home()` 里写 `app.today = time.Now().Format(...)`，每帧都在改状态，
> 视图永远「脏」，帧率会掉下去。正确做法是 `rollOver()`：只在日期真的变了时才写。

### 2.2 元素只活一帧

```go
// ❌ 下一帧就是过期值
type App struct { saveBtn ui.Element }

// ✅ 要持久身份用 Handle / ListState
type App struct {
    diaryList ui.ListState
}
```

`ui.NewTester` 与开发模式会主动报错让你发现问题；生产模式会退化成空操作。

同样，**不要把 `*ui.Context` 存进结构体或 goroutine**。后台任务要改状态时，
用 `Window.Update(func(){...})`（在主线程执行并重绘），或者拿 `c.Services()`。

### 2.3 输入与动作的时序

| 写法 | 何时运行 | 用途 |
| --- | --- | --- |
| 用户输入 | 立即写入绑定的变量 | 文本、勾选、滑块 |
| `.Changed()` | 本次构建返回后的下一帧 | 值变化后的联动 |
| `.Submitted()` | 单行输入回车后的那一帧 | 回车提交 |
| `if x.Clicked()` | 构建中同步读取 | 简单且不改集合的动作 |
| `.OnClick(fn)` | 构建结束、绑定值已写入之后 | 改集合、落库 |
| `.OnChange(fn)` | 同上，针对值变化 | 勾选后落库 |
| `c.Shortcut(...)` | 构建中同步读取 | 窗口级快捷键 |

一个例子：

```go
add := ui.PrimaryButton(c, "添加").OnClick(app.addTodo)
add.Disabled(strings.TrimSpace(app.todoDraft) == "")
```

`addTodo` 读到的是用户刚输入的最新值；`Disabled` 用的是上一帧的值——
输入框刚有字时按钮还灰着，下一帧才亮。这是「输入按用户操作那一帧的选项生效」的规则，
不是 bug。

### 2.4 Key

同级之间唯一。列表里几乎每个控件都该有：

```go
ui.Checkbox(c.Key("pt-"+p.ID), &p.Done, "")   // 要点
ui.Button(c.Key("todo-del-"+todo.ID), "")      // 删除
ui.Column(c).Key("day-card-" + date)           // 整张卡片
```

`c.Key(...)` 只对下一个控件生效；容器要先 `.Key()` 再 `.Children()`，
这样它给子元素一个独立的身份作用域。

### 2.5 布局

`ui.Row` / `ui.Column` / `ui.Box` / `ui.Scroll` / `ui.List` 加上
`Grow` `Fill` `Padding` `Gap` `Width` `MinWidth`，就是熟悉的 flexbox。

最容易忘的一条：**`Grow(1)` 里放长文本要加 `MinWidth(0)`**，否则内容宽度会撑破父容器。

```go
ui.Column(c).Grow(1).MinWidth(0).Children(func() { ... })
```

### 2.6 主题

`c.Theme()` 返回当前主题，`c.SetTheme(&t)` 替换它。MyGo 每帧都会用
「跟随系统外观 + 桌面偏好」的默认主题重建上下文，所以每帧从干净的
`LightTheme()/DarkTheme()` 出发是安全的：

```go
t := *ui.LightTheme()            // 或 ui.DarkTheme()
t = *t.WithPreferences(c.Preferences())   // 系统对比度、字号缩放
t.Background = ui.Hex("#fffcf8")          // 覆盖成暖纸色
t = *t.WithAccent(ui.Hex("#c2410c"))      // 固定品牌橙
c.SetTheme(&t)
```

顺序有讲究：`WithAccent` 会推导 `AccentHover/Pressed/Selection/Focus`，
所以放在最后，它推导出来的颜色不会被前面的赋值覆盖。

## 3. 分层与依赖方向

```
model   ←  store   ←  view  ←  main
  ↑          ↑         ↑
纯数据      SQLite    界面     装配
```

依赖只能向右：`model` 不认识数据库，`store` 不认识界面，`view` 不直接开文件。
想换存储只动一层。

`App` 就是「整个界面的状态」：

```go
type App struct {
    store  *store.Store
    router *ui.Router
    win    *mygo.Window          // 后台任务用它回到主线程

    days  []model.Day            // 全部日子，倒序
    today string
    settings model.Settings

    diaryList ui.ListState       // 列表的持久状态
    query     string
    filtered  []int              // 每帧算出的过滤结果
    // …
}
```

`days` 是全量的：一本日记一年几百天、几 MB，一次读进内存，
搜索、统计都是内存操作。**在这个数据规模上，全量进内存是正确的选择。**

## 4. 数据建模

一条学习记录的结构从早期的 Markdown 笔记演变而来：

```go
type Day struct {
    Date    string  `json:"date"`
    Entries []Entry `json:"entries"`
    Todos   []Todo  `json:"todos"`
}

type Entry struct {
    ID      string  `json:"id"`
    Subject string  `json:"subject"`   // 计算机组成原理
    Chapter string  `json:"chapter"`   // 第 4 章 存储系统
    Section string  `json:"section"`   // 第 8 节 虚拟存储器
    Points  []Point `json:"points"`    // 要点
    Note    string  `json:"note"`
    Minutes int     `json:"minutes"`
    At      string  `json:"at"`        // "21:30"
}
```

设计中值得说明的几点：

- **章节拆成「章 / 节」两个字段**，而不是一个带 `>>` 的字符串。
  用户不该为了分隔符去记语法；两个输入框都能留空，只写科目也能保存。
  展示时用 `Entry.TopicParts()` 拼成面包屑。
- **要点是独立的结构**（`Point` 有 `ID` 和 `Done`），不是一段文本。
  这样「已复习」的勾选状态才能被保存和恢复。
- **ID 用随机十六进制**（`model.NewID()`），不用自增：数据在设备之间复制、
  导入备份时不会冲突。
- **不存完整时间戳**：日期已经是主键，`At` 只记 `"15:04"`，够用且更短。

## 5. 存储：SQLite

### 5.1 为什么换掉 JSON

早期版本一天一个 JSON 文件，人可读、可 Git、可手改。数据量一大就暴露问题：
按关键词搜索要读全部文件、统计要全量解析、写入要整文件重写。
换成 SQLite 后：单文件、事务、索引，读一周的数据只需几条 SQL。

### 5.2 MyGo 的 sqlite 插件

插件是 `github.com/egoist/mygo/plugins/sqlite`，**不是** `database/sql` 的驱动：
它通过 purego 调用一个预编译的 SQLite 核心库，没有 cgo。

```go
db, err := sqlite.Open(ctx, path, sqlite.OpenOptions{})
defer db.Close()

_, err = db.Execute(ctx, `CREATE TABLE IF NOT EXISTS notes (title TEXT)`)
rows, err := db.Query(ctx, `SELECT title FROM notes`)
// rows.Columns []string, rows.Values [][]any
_, err = db.Transaction(ctx, []sqlite.Statement{
    {SQL: `INSERT INTO notes VALUES (?)`, Args: []any{"first"}},
})
```

几个必须知道的约束：

- **`DB` 不是 `*sql.DB`**：没有 `Prepare`、`Scan`、`Rows.Next`。查询一次返回全部行
  （`Rows.Values`），大结果集要自己 `LIMIT`。
- **`Execute` 只执行一条语句**；多条用 `Transaction`，它内部是 `BEGIN IMMEDIATE`，
  出错整体回滚。并且**禁止在 SQL 里手写 `BEGIN` / `COMMIT`**。
- **连接可以从任意 goroutine 使用**，同一个 `*DB` 上的操作会串行排队。
- **外键默认开启**，因此删除 `days` 会自动级联删除 `entries`、`points`、`todos`。
- **没有迁移框架**：用 `CREATE TABLE IF NOT EXISTS` 加 `PRAGMA user_version` 自己管版本。

### 5.3 表结构

```sql
CREATE TABLE days (
    date       TEXT PRIMARY KEY,
    created_at INTEGER NOT NULL DEFAULT 0
);
CREATE TABLE entries (
    id        TEXT PRIMARY KEY,
    date      TEXT NOT NULL REFERENCES days(date) ON DELETE CASCADE,
    subject   TEXT NOT NULL,
    chapter   TEXT NOT NULL DEFAULT '',
    section   TEXT NOT NULL DEFAULT '',
    note      TEXT NOT NULL DEFAULT '',
    minutes   INTEGER NOT NULL DEFAULT 0,
    at        TEXT NOT NULL DEFAULT '',
    position  INTEGER NOT NULL DEFAULT 0
);
CREATE TABLE points (
    id       TEXT PRIMARY KEY,
    entry_id TEXT NOT NULL REFERENCES entries(id) ON DELETE CASCADE,
    text     TEXT NOT NULL,
    done     INTEGER NOT NULL DEFAULT 0,
    position INTEGER NOT NULL DEFAULT 0
);
CREATE TABLE todos (
    id       TEXT PRIMARY KEY,
    date     TEXT NOT NULL REFERENCES days(date) ON DELETE CASCADE,
    text     TEXT NOT NULL,
    done     INTEGER NOT NULL DEFAULT 0,
    at       TEXT NOT NULL DEFAULT '',
    position INTEGER NOT NULL DEFAULT 0
);
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);
```

`position` 是排序用的：列表顺序由用户的操作决定，不能依赖插入顺序。

### 5.4 写入：整天替换

保存一天时，在一个事务里删掉这一天的条目与待办，再按当前内存状态重新插入。
一天的记录只有几十条，这是最简单且不会产生「部分更新」的做法：

```go
stmts := []sqlite.Statement{
    {SQL: `INSERT OR IGNORE INTO days (date, created_at) VALUES (?, ?)`, Args: []any{day.Date, now}},
    {SQL: `DELETE FROM entries WHERE date = ?`, Args: []any{day.Date}},
    {SQL: `DELETE FROM todos WHERE date = ?`, Args: []any{day.Date}},
}
for i, e := range day.Entries {
    stmts = append(stmts, insertEntry(e, i))
    for j, p := range e.Points {
        stmts = append(stmts, insertPoint(e.ID, p, j))
    }
}
db.Transaction(ctx, stmts)
```

如果这一天既没有记录也没有待办，就把它整行删掉（`ON DELETE CASCADE` 会带走子表），
界面上也就不会出现空卡片。

### 5.5 备份与迁移

- **导出**：把所有日子与设置写成一个 JSON 文件（`store.Export`）。
- **恢复**：清空数据库，逐天写入，再写设置（`store.Restore`），界面上有二次确认。
- **旧数据导入**：`store.ImportJSONDir` 读取早期 `data/2026-11-13.json` 这样的文件，
  跳过 `settings.json` 与读不出来的文件，按日期覆盖写入。

备份里带 `app: "FlowLog"` 与 `format: 1`，读取时先校验再解析，
避免把别的 JSON 当备份恢复。

### 5.6 原生库的坑

sqlite 插件的核心库是预编译的动态库，第一次运行时会下载到
`<缓存目录>/mygo/natives/<sha256>/Sqlitecore.dll`。本机第一次跑测试时下载超时，
手动把文件放进缓存目录后一切正常：

```powershell
$sha = "029fd2db48c3cc30de13f0a5f33c7604460f8f61496b9e641d7de7e394d3f8e6"
New-Item -ItemType Directory -Force "$env:LOCALAPPDATA\mygo\natives\$sha"
Invoke-WebRequest "https://github.com/egoist/mygo/releases/download/native-sqlitecore/Sqlitecore-windows-amd64-029fd2db48c3.dll" `
  -OutFile "$env:LOCALAPPDATA\mygo\natives\$sha\Sqlitecore.dll"
```

也可以用 `MYGO_NATIVE_SQLITECORE` 指向任意一份该库。
**打包后的应用不会下载任何东西**：`mygo build` 会把对应的库复制到应用旁边
（本次构建的产物里就能看到 `Sqlitecore.dll`）。

## 6. 界面实现

### 6.1 侧边栏与路由

```go
ui.Column(c).Width(232).Background(t.Surface).BorderWidth(0, 1, 0, 0).Children(func() {
    app.brand(c)                       // 应用图标 + 流记 / FLOWLOG
    page := app.router.Path()
    if ui.Sidebar(c, &page, func() {
        ui.SidebarItem(c, "/", iconHome, "首页")
        ui.SidebarItem(c, "/diary", iconBook, "日记")
        ui.SidebarItem(c, "/todo", iconCheckCircle, "待办")
        ui.SidebarItem(c, "/settings", iconSettings, "设置")
    }).Grow(1).Label("主导航").Changed() {
        app.router.Push(page)          // 选中项就是路由路径
    }
    app.sidebarFooter(c)               // 主题切换 + 版本号
})
```

用 `ui.Sidebar` 而不是自己拼按钮：白拿键盘导航、选中态和一棵无障碍树
（读屏会把它读成源列表）。

### 6.2 首页：必应每日一图

背景图来自 `https://bing.biturl.top/`，返回 JSON：

```json
{
  "start_date": "20261112",
  "end_date": "20261113",
  "url": "https://www.bing.com/th?id=OHR.AbrahamCanada_ZH-CN0344365912_1920x1080.jpg",
  "copyright": "亚伯拉罕湖，艾伯塔省，加拿大 (© Guang Cao/Getty Images)",
  "copyright_link": "https://www.bing.com/search?q=…"
}
```

流程：先读当天缓存（`<缓存目录>/FlowLog/background/2026-11-13.jpg`），
没有就在 goroutine 里下载 → 解码为 `*ui.Bitmap` → `Window.Update` 回到主线程写入
`app.bg`。取不到就继续用品牌渐变，界面不受影响。

```go
box := ui.Box(c).Height(212).Radius(18).Clip()
box.Children(func() {
    ui.Image(c, app.bg).Absolute().Top(0).Left(0).Right(0).Bottom(0).Fit(ui.Cover).ZIndex(-3)
    ui.Box(c).Absolute().Top(0).Left(0).Right(0).Bottom(0).ZIndex(-2).
        Gradient(ui.Transparent, ui.RGBA(0, 0, 0, 0.78), 178)
    heroContent(c, quote, "Bing 每日一图 · "+app.bgCopyright)
})
```

两个关键点：

- 绝对定位的子元素默认画在流内兄弟**之上**，所以照片与压暗层要 `ZIndex(-3)` / `ZIndex(-2)`。
- 文字放在卡片底部，正好压在渐变压暗的那一端，白色文字才够清楚；
  图片署名也在这里，满足 Bing 的署名要求。

### 6.3 日记页

```
页头：日记 · 共 4 天 · 9 条要点        [搜索框] [＋ 写日记]
────────────────────────────────────────────────────────
┌ 11 月 13 日  星期五  [今天]  4 条要点           ✎      ┐
│  [计算机组成原理]  第 4 章 存储系统 › 第 8 节 …  ⏱45分  ✎ │
│  ☐ 页式虚拟存储器的地址映射和页表                        │
│  ☑ 缺页中断的处理流程                                    │
└────────────────────────────────────────────────────────┘
```

- **`ui.List` 而不是 `ui.Scroll` + 循环**：只构建视口内的行，并测量真实行高。
- **`ListState.Key` 用日期**：搜索过滤、插入新的一天都不会让行内状态串位。
- **每张卡片右上角只有一个「＋ 写日记」**（页头），卡片上不再放重复的加号；
  补记旧日期用弹窗里的日期选择。
- **危险操作 hover 才出现**：删除整天只在鼠标移入卡片时显示。
- **要点用真正的 `ui.Checkbox`**（可键盘、可读屏），标签留空、文字自己排，
  这样勾选后的删除线由我们控制。
- **搜索是纯内存过滤**，命中科目、章节、备注、要点、待办与日期。

### 6.4 写日记弹窗

```go
ui.Modal(c, &app.ed.Open, func() {
    _, windowHeight := c.Size()
    formHeight := max(windowHeight-320, 160)   // 表单高度跟着窗口走

    ui.Column(c).Width(520).Children(func() {
        /* 标题行 */
        ui.Scroll(c).MaxHeight(formHeight).Children(func() {
            /* 日期 + 科目 */
            /* 章 + 节（两个可选输入框） */
            /* 要点（多行，一行一条） */
            /* 学习时长 + 备注 */
        })
        ui.Box(c).Height(1).Background(t.Border).Margin(6, -2, 0)   // 分隔线
        ui.Row(c).Gap(8).Padding(16, 0, 2).Children(func() { /* 取消 / 保存 */ })
    })

    if c.Shortcut(ui.Cmd, ui.KeyEnter) { app.saveEditor() }
})
```

细节：

- `ui.Modal` 自带遮罩、居中面板、圆角与投影，只需要往里放内容。
- **表单区域用 `Scroll` + 动态 `MaxHeight`**：窗口矮时表单滚动，按钮始终可见。
- **分隔线与底部按钮之间要有间距**：`Margin` 让线离开表单，`Padding(16,0,2)` 让按钮离开线。
- **校验失败不关弹窗**，把错误显示在表单里；同时把焦点送回输入框。
- **编辑时保留勾选状态**：按文本匹配旧要点，把 `Done` 与 `ID` 带过去。

```go
for i := range entry.Points {
    for _, p := range old.Points {
        if p.Text == entry.Points[i].Text {
            entry.Points[i].ID, entry.Points[i].Done = p.ID, p.Done
            break
        }
    }
}
```

### 6.5 待办页

- 输入框回车即添加（`Submitted()`）。
- 删除后弹一条带「撤销」的提示，`OnAction` 里按原位置插回去。
- 列表放在一张卡片里，高度贴着内容；待办多了才滚动。
- 行高固定 36：鼠标移上去时右侧删除按钮出现，如果行高随内容变化，
  列表会因为内容变高而冒出滚动条，鼠标一滑就闪。同时
  `.ScrollbarAxes(false, true)` 关掉横向滚动条。

### 6.6 设置页

从上到下：账户 → 外观 → 数据 → 快捷键 → 关于与更新。
「关于」放在最后，符合「设置页同时也是关于页」的定位。

- **账户**：`TextInput` 直接绑定 `app.settings.UserName`，回车或点保存写库。
- **外观**：`Segmented` 只有浅色 / 深色两项。
- **数据**：统计行、数据库绝对路径（可复制）、三个动作按钮、两行说明。
- **关于**：图标、名称、版本、作者、仓库、许可证、技术栈、版本更新。

### 6.7 首次启动引导

`settings.Onboarded` 为 false 时弹出一个询问称呼的小弹窗：

```go
ui.Modal(c, &app.onboarding.Open, func() {
    ui.Text(c, "先认识一下").Font(fontSerif).FontSize(20).Bold()
    ui.Field(c, "称呼", func() { ui.TextInput(c.Key("onboarding-name"), &app.onboarding.Name).AutoFocus() })
    // 跳过 / 开始使用
})
```

关掉弹窗也算完成引导（设置里随时能改），用户不会被困在一个必须填写的表单里。

### 6.8 原生文件对话框

备份与导入要用系统的文件选择框。它们会阻塞，所以整段跑在 goroutine 里，
结果通过 `Window.Update` 回到主线程：

```go
go func() {
    path, err := mygo.Dialog.Save(mygo.SaveDialogOptions{
        Parent: app.win, Title: "导出备份",
        DefaultPath: "flowlog-backup-" + model.Today() + ".json",
        Filters: []mygo.FileFilter{{Name: "JSON 备份", Extensions: []string{"json"}}},
    })
    if err != nil || path == "" { return }
    if err := app.store.ExportFile(path); err != nil {
        app.post(func() { app.toastError("导出失败", err.Error()) })
        return
    }
    app.post(func() { app.toast("备份已导出", path) })
}()
```

`app.post` 是 `win.Update` 的封装：**后台 goroutine 改界面状态一律经过它**，
否则就是数据竞争。

## 7. 字体与排版

标题用衬线体，正文用系统默认的无衬线体，形成层次：

```go
const fontSerif = "Georgia, Cambria, Times New Roman, Noto Serif SC, Source Han Serif CN, STSong, SimSun, Songti SC"
ui.Text(c, "日记").Font(fontSerif).FontSize(25).Bold()
```

- MyGo 的 `Font` 接受逗号分隔的字体栈：按顺序取第一个系统有的字体，
  缺某个字时自动落到下一个。拉丁字母用 Georgia，中文落到 Noto Serif SC / 宋体。
- 用之前先列出系统字体确认可用性（`ui.FontFamilies()`），
  不要凭记忆写字体名。
- **斜杠数字**：Georgia 默认使用旧式数字（old-style figures），
  `0` 会变成小写 `o` 的高度。统计数字要加 `FontFeatures("lnum")` 换成等高数字：

```go
ui.Text(c, "4 天").Font(fontSerif).FontFeatures("lnum")
```

## 8. 八个真实的坑

### 坑 1：一边遍历一边改集合

```go
// ❌ 点一下删除，可能少删一条，甚至崩
for _, todo := range app.days[ti].Todos {
    ui.Button(c, "删除").OnClick(func() { app.removeTodo(todo.ID) })
}
```

**规则**：会改集合的动作交给 `OnClick` / `OnChange`（在本帧构建完成之后运行），
并在动作内部按 ID 重新查找下标，不依赖遍历时的副本。

### 坑 2：绑定「派生值」会丢

```go
// ❌ 每帧都从 settings 重新算，用户刚点的值下一帧被覆盖回去
idx := themeModeIndex(app.settings.Theme)
ui.Segmented(c, &idx, ...)
```

两条正确写法：

```go
// 1) 控件本身是数据源：绑定真实字段
ui.Segmented(c, &app.todoFilter, "全部", "进行中", "已完成")

// 2) 立刻回写：控件在构造返回时已经写入，所以紧接着比较、立刻保存
choice := 0
if app.settings.Theme == model.ThemeDark { choice = 1 }
ui.Segmented(c, &choice, "浅色", "深色")
if choice == 1 && app.settings.Theme != model.ThemeDark {
    app.settings.Theme = model.ThemeDark
    app.saveSettings()
}
```

### 坑 3：把 Element 存起来

```go
// ❌ 下一帧已经过期
app.panel = ui.Popover(c, btn, &open, func() { … })
```

弹层、按钮，凡是 `ui.Element` 都只在当帧有效。要「打开一个浮层」，
存的是布尔值，浮层在同一个作用域里按它重建。

### 坑 4：列表身份

过滤、排序后的列表，必须给 `ListState.Key`：

```go
app.diaryList.Key = func(i int) any { return app.days[app.filtered[i]].Date }
```

否则搜索时第 1 行从「11 月 13 日」变成「11 月 12 日」，
行内的滚动位置、焦点、草稿都会串位。

### 坑 5：弹窗里的快捷键

窗口级快捷键在模态弹窗打开时**不应该**生效，否则正在写的内容会被 `⌘N` 清空。
MyGo 的 `c.Shortcut` 在弹窗外构建时返回 false，所以把全局快捷键写在 `View` 顶层、
把弹窗内快捷键写在 `Modal` 的 children 里即可。有测试盯着（见第 10 节）。

### 坑 6：按钮自带的 label 会排在 children 前面

```go
// 渲染成「写日记 ＋」，图标跑到文字后面
add := ui.PrimaryButton(c, "写日记")
add.Children(func() { ui.Icon(c, iconPlus) })
```

要「图标在文字前」，就传空 label，自己拼：

```go
add := ui.PrimaryButton(c, "").Label("写日记")   // Label 给读屏用
add.Children(func() {
    ui.Icon(c, iconPlus).FontSize(14)
    ui.Text(c, "写日记").SingleLine()
})
```

### 坑 7：行高变化导致滚动条闪烁

待办行里的删除按钮只在 hover 时出现，按钮 28px 比文字高，行高跟着变 →
列表内容超过最大高度 → 冒出滚动条 → 指针位置变化 → 按钮消失……如此循环。
解决办法是**固定行高**（`Height(36)`），并关掉不需要的横向滚动条
（`ScrollbarAxes(false, true)`）。

### 坑 8：`App.Name()` 在某些时机是空的

```go
// ❌ 在 WhenReady 里，App.Name() 可能还没有值，路径变成 %APPDATA%\data
dir, _ := mygo.App.Path(mygo.PathUserData)

// ✅ 自己拼目录名
base, _ := mygo.App.Path(mygo.PathAppData)
dir := filepath.Join(base, "FlowLog", "data")
```

凡是「路径里拼了应用名」的地方，都要在真正打包后的版本里试一次。

## 9. 视觉验证

原生 UI 同样可以被「截图检查」，而且比 Web 更方便。

### 9.1 三种方式

| 方式 | 命令 | 优点 | 局限 |
| --- | --- | --- | --- |
| Tester 内存渲染 | `go test -run TestPreview` | 秒级、无窗口、可批量、可进 CI | 软件光栅化，字体渲染与真机略有差异 |
| 自动化插件截真窗口 | `mygo-automation screenshot` | 真实 GPU 渲染、真实窗口与缩放 | 需要 `-tags e2e` 构建并运行真窗口 |
| 人眼看窗口 | `go tool mygo dev` | 最真实 | 需要人（或截图） |

做法：**先用 Tester 出图快速迭代设计，最后用真窗口截图验收**。

### 9.2 Tester 渲染每个页面

```go
func render(t *testing.T, dir, name string, app *App, w, h int) {
    tt := ui.NewTester(app.View, w, h)
    for i := 0; i < 3; i++ { tt.Advance(16 * time.Millisecond) }  // 让 List 量完行高
    tt.Advance(5 * time.Second)                                   // 让提示消失
    img := tt.Image()
    f, _ := os.Create(filepath.Join(dir, name+".png"))
    png.Encode(f, img)
}
```

- **多走几帧**：`ui.List` 第一帧还不知道每行多高，会用估算值。
- **状态就是截图**：想截弹窗，就 `app.openEditor(...)` 后再 `NewTester`；
  想截深色，就改 `app.settings.Theme`。
- 一次渲染 12 张：四个页面、三个深色页面、两个弹窗、引导、窄窗口、高窗口。

### 9.3 真窗口截图

```bash
go build -tags e2e -o .mygo/e2e/flowlog-e2e.exe .
MYGO_AUTOMATION=C:\temp\flowlog.sock .\.mygo\e2e\flowlog-e2e.exe

mygo-automation open --socket C:\temp\flowlog.sock
mygo-automation snapshot -i
mygo-automation press '@e5' --settle
mygo-automation screenshot C:\temp\shot.png
```

踩过的几个点：

- PowerShell 里 `@e5` 会被当成 splatting，必须写成 `'@e5'`。
- 以 `-` 开头的参数会被当成命令行开关，用 `--` 分隔。
- **socket 路径不要放中文**，否则插件可能静默不监听。
- 截图可能比动作慢一拍，先 `wait --settle` 再 `screenshot`。

### 9.4 截图帮我发现的问题

| 在图里看到的 | 原因 | 怎么改 |
| --- | --- | --- |
| 每张卡片三个铅笔图标 | 卡片头与每条记录各一个 | 去掉卡片头的加号，记录铅笔降透明度 |
| 弹窗底部被切掉一半 | `Scroll` 固定 `MaxHeight` | 改为按窗口高度计算 |
| 首页两栏卡片不等高 | 卡片没 `FillHeight` | `AlignItems(Stretch)` + `.FillHeight()` |
| 「写日记」的加号在文字后面 | 按钮 label 先于 children | 空 label + 自己拼图标与文字 |
| 日期格子数字偏左上 | 文本自身不参与居中 | 放进 `Box(...).Center()` 里 |
| 统计数字 `0` 像小写 `o` | Georgia 的旧式数字 | `FontFeatures("lnum")` |
| 待办悬停时冒出滚动条 | 行高随按钮变化 | 固定行高 + 关闭横向滚动条 |
| 设置页分段控件拉满整行 | 列容器默认拉伸子元素 | 显式 `Width(180)` |
| 快捷键那列文字换行 | 标签列太窄 | 列宽 96 + 文案写成 `1…4` |

**这些问题没有一个是「想」出来的，全是看图看出来的。**

## 11. 可访问性与键盘

原生 UI 的无障碍是白送的，前提是用对控件：

- 按钮用 `ui.Button`，不用 `ui.Text(...).OnClick(...)`。
- 图标按钮给 `.Label("…")`，图标本身作为装饰。
- 输入框配 `ui.Field(c, "科目", ...)`。
- 列表用 `ui.List` / `ui.Sidebar`，它们自己会报「列表 / 树」。

自动化快照就是验收单——如果某个按钮没有名字，这里会是空的：

```
@e3 [tree] "主导航" selectable
  @e4 [treeItem] "首页" key="/" checked selectable
@e6 [textField] "称呼" key=onboarding-name focused
@e76 [textField] "章节" key=editor-chapter
@e79 [textField] "要点" key=editor-points multiline
```

键盘：`Tab` 在控件间移动（弹窗内循环），`⌘/Ctrl + N` 写日记、`1…4` 切页面、
`F` 搜索、`Enter` 保存、`Esc` 关弹窗。

对比度：`WithAccent` 会按对比度自动给按钮选黑字或白字。品牌橙 `#c2410c`
配白字约 5.2:1；更亮的 `#ff8904` 只有 2.4:1，所以界面强调色用深一档的橙，
亮橙只出现在图标里。

## 12. 性能

- 每帧零 I/O：数据在内存，写入只在用户动作时发生。
- 列表虚拟化：只构建视口内的行。
- 过滤复用切片：`app.filtered = app.filtered[:0]`。
- SQLite 一次保存是一个事务，几十条语句，1~3 ms。
- 背景图每天只下载一次，之后读缓存。
- 主题每帧重建：一次结构体拷贝 + 若干赋值，可以忽略。

不要在 view 里做正则、排序、读文件、发网络请求。

## 13. 打包、发布与自动更新

### 13.1 本地打包

```bash
go tool mygo build
# build/windows-amd64/FlowLog.exe + flowlog-setup-0.3.0-amd64.exe
```

`mygo build` 会：编译为 GUI 程序（Windows 下没有控制台窗口）、复制资源
（图标与 `Sqlitecore.dll`）、生成安装包，并（在提供了私钥时）生成带签名的更新包。

### 13.2 更新是怎么工作的

1. `mygo.json` 里配置了 `updates.publicKey` 与 `updates.github`。
2. 构建时用私钥给更新包签名，并把公钥编译进程序。
3. 应用启动后（或用户在设置页点「检查更新」）向
   `https://github.com/<owner>/<repo>/releases/latest/download/update-<target>.json`
   取清单；有更高版本就下载、用内置公钥验签、替换文件，然后
   `mygo.App.Relaunch()` 重启。
4. 只有同一把私钥签名的更新会被接受。

代码在 `internal/view/update.go`：

```go
up, err := mygo.Updater.Check(ctx)          // nil 表示已是最新
err = up.Install(ctx, func(done, total int64) { /* 进度 */ })
mygo.App.Relaunch()
```

开发构建里 `mygo.Updater.Enabled()` 为 false，所以设置页会显示
「开发版与包管理器安装的版本不支持自动更新」。

### 13.3 一次性配置

1. 生成密钥对（已生成，公钥写在 `mygo.json`）：

```bash
go tool mygo keygen
# C:\Users\<you>\AppData\Roaming\mygo\update-keys\mygo-update.key  ← 私钥，保密
# C:\Users\<you>\AppData\Roaming\mygo\update-keys\mygo-update.pub  ← 公钥，写进配置
```

2. 把**私钥文件内容**加到 GitHub 仓库的 Actions secret：

```bash
gh secret set MYGO_UPDATER_PRIVATE_KEY < "%APPDATA%\mygo\update-keys\mygo-update.key"
```

私钥丢失后已安装的用户将无法再收到更新；私钥泄露则任何人都能伪造更新。
把 `mygo-update.key` 备份到密码管理器，不要提交进仓库。

### 13.4 发布

```bash
# 1. 改 mygo.json 的 version，补 CHANGELOG.md 的 "## <版本号>" 一节
# 2. 提交
git commit -am "release: v0.3.1"
git tag v0.3.1
git push origin v0.3.1
```

工作流 `.github/workflows/release.yml` 会：

1. 创建草稿 Release；
2. 在三个 runner 上并行构建 `darwin/arm64,darwin/amd64`、
   `windows/amd64,windows/arm64`、`linux/amd64,linux/arm64`；
3. 每个产物上传到同一个草稿 Release（含 `update-<target>.json` 与签名）；
4. 全部成功后取消草稿状态，应用端即可看到新版本。

没有签名证书也能跑通自动更新；但 macOS 上未签名的应用在别人机器上会被
Gatekeeper 拦截，Windows 会弹 SmartScreen 警告。正式分发需要配置
Apple Developer ID + notarize 与 Windows 代码签名证书（见 README 的可选 secrets）。

## 14. 还可以怎么做

1. **按科目统计**：`day.Subjects()` 已有，可以加「这一科这周几条要点」的图表。

   也会跟着系统语言走。
6. **自动备份**：每次启动把数据库复制一份到 `backups/`，保留最近 7 份。

刻意没做的：账号系统、云同步、富文本编辑器。一个本地日记工具，
把「记录」这件事做顺手就够了。

## 15. 排错清单

| 现象 | 先看这里 |
| --- | --- |
| 启动白屏 | `main.go` 是否 `Content: ui.View(app.View)`；控制台是否 panic |
| 启动即退出 | 数据库打不开：路径、权限、`Sqlitecore.dll` 是否在 |
| `native: the implementation of Sqlitecore is not built` | 原生库没下载成功，见 5.6 节 |
| 点按钮没反应 | 动作是否写在 `Clicked()` 里但被后续代码覆盖；是否忘了 `.OnClick` |
| 输入的值「弹回去」 | 是否绑定了每帧重算的局部变量（坑 2） |
| 列表状态乱跳 | 是否给 `ListState.Key`（坑 4） |
| 文字溢出 | 加 `MinWidth(0)` + `.SingleLine()` |
| 图标与文字顺序反了 | 按钮 label 与 children 的顺序（坑 6） |
| 保存后界面没变 | 是否在 `Draw` 回调等非动作路径里改状态 |
| 文件没写进去 | 看 `store.SaveDay` 的错误；数据库是否可写 |
| 背景图不显示 | 网络、`bing.biturl.top` 是否可达；缓存目录权限 |
| 自动更新没反应 | 是否为 dev 构建；`updates` 配置与私钥是否匹配 |
| 自动化连不上 | socket 路径别有中文；是否带 `-tags e2e`；`MYGO_AUTOMATION` 是否传进进程 |
| 中文乱码 | 终端 `chcp 65001`；文件本身是 UTF-8 |
